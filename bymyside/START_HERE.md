# bymyside 初始化指引（由助手执行）

用户只需在 AI 办公 agent 的项目中请求初始化。你负责下面的准备工作，不把目录结构、配置提示词和内部维护交给用户。

## 1. 加载与检查

读取 `skill/SKILL.md`、共同边界和对象归属。确认项目资料可持久读写、当前日期/用户时区可获取、宿主是否提供创建/读取定时任务的工具，以及任务运行时能否访问同一份资料。默认目标是自动晨间、晚间和周流程；手动触发仅作为网络、调度或平台能力不足时的降级。

不以某个品牌、项目名称或技能导入成功推断全部能力就绪。若缺少关键能力，准确说明哪一步尚不能完成，并尽量完成独立的准备工作。只用已公开的工具或平台支持的配置方法，不编造工具名或写入猜测的私有调度配置。

## 2. 轻量了解与导入日程

先接收用户已有输入，再自然邀请：可以发一份日程文件/截图、授权读取日历，或直接说固定安排。已有答案不重复问；用户不想导入也能开始。只问影响当前安排的缺口，不发完整人生问卷。

使用当前平台可用的文件解析、图片读取或已授权日历工具。无法解析时说明具体缺口，邀请补充必要部分，不猜测截图或文件内容。导入只读，不默认向外部日历新建/修改事件，不扫描用户未提供或未授权的资料。

整理开始/结束时间、时区、重复规则、生效范围、例外、来源与最近确认时间；包括工作、会议、课程、约会、通勤与生活。确认会影响排期的模糊字段、冲突与时区。保留原文件，不覆盖原日历；更新导入时查重、应用已确认变更，不重复累加固定事项。不要把空白日程当作全天可工作。

了解用户最近在意的事和希望保留的生活时间。无长期目标时标待确认，可以先从眼前责任和零碎想法开始。

## 3. 建立私人记录

检查现有 `.bymyside/memory/`，存在则增量更新，不覆盖已有事实。不存在时建立：

- `MEMORY.md`：时区、用户确认的节奏/接收位置、资料权限、平台能力、初始化状态、自动化标识与创建结果。
- `life-map.md`：方向、当前阶段与长期取舍；未知方向标待确认。
- `projects.md`：已有责任、项目与候选想法。
- `schedule.md`：日程表与有效约束。
- `week-plan.md` 与用户当地日期日志：近期安排与进展。

示例在 `examples/memory/`，仅供结构参考；不得把虚构人物的安排写成用户事实。对外推送不复制原始个人日记。旧工作区若只有 `.workbuddy/`，先确认迁移位置和方式，不能自动删改旧资料或同时维护两套事实。

## 4. 配置三项自动陪伴

在一次自然确认中确定时区、晨间/晚间/每周时间、接收位置与运行授权。可以提出示例节奏：08:30 晨间、21:00 晚间、周日 18:00 周回顾；这些不是已获授权的默认值。用户已提供并授权时直接使用，不重复请求。

确认后优先使用本平台自动化工具创建任务，执行提示分别来自 `automations/morning.md`、`evening.md`、`weekly.md`。填入实际项目位置、时区与接收方式；所有任务加载项目中的同一版规则，并访问同一份持久资料。不要让平台的独立定时会话失去项目数据。

创建前列出已有任务：相同项目与流程已存在就复用或按授权更新，不重复创建。创建失败或响应不明时先查询实际结果，不盲目重试。保存平台返回的任务标识、节奏、状态和接收位置，再回读核验。平台要求的确认点击由用户完成。

若平台只能由用户保存配置，先准备三份完整可复制配置，只让用户完成平台要求的最后一步；此时状态写“待平台确认”。没有创建工具时不能伪称已经自动配置。普通任务结果可使用宿主自带通知；额外聊天软件/日历渠道只有在对应连接器存在且已获授权时才配置。

## 5. 第一份安排与结果

依据已知日程、责任、方向和状态，拟一份可调整的近期安排。配置完成后回读项目记录，确认能重新取得当前状态。授权测试运行时再检查实际结果与通知，平台的“创建成功”不等于“消息已送达”。

对用户只交付：第一份安排、简短的晨间/晚间/每周配置结果，以及确实需要其完成的操作。每项配置区分“已创建/已启用/待确认/失败”，实际触发未验证时如实说明，不给用户一长串内部文件清单。

日常运行后按规则接续与维护，不要求用户手动发起每日/周流程。网络或调度中断后使用实际时点规划，不补发整套过期安排。
