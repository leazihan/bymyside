# 对象与信息归属

## 当前数据

| 对象 | 必要信息 | 维护位置 |
|---|---|---|
| 目标与领域 | 方向、当前阶段重点、持续责任或投入 | life-map |
| 阶段规划 | 阶段重点、里程碑、长期取舍、关联项目 ID | life-map |
| 项目 | 稳定 ID、预期结果、状态、期限类型、进展、剩余工作、依赖、下一里程碑、安排窗口 | projects.md |
| 常规投入 | 所属领域、目的、节奏、可调整范围 | life-map |
| 未定时想法 | 目标关联、价值、时机与延迟代价、投入、依赖、建议路径、复核日期 | projects.md 的候选区 |
| 固定约束 | 来源、适用范围、有效期、例外 | 日程表或相应参考资料；life-map 保留指向 |
| 本周安排 | 周目标、项目分配、每日结果、容量缺口、待决定取舍 | week-plan.md |
| 今日安排与进展 | 时间块、项目与周目标关联、完成标准、已知进展、剩余工作、重要变化 | 当日日志 |
| 完成与历史 | 普通完成简记；重要结果与交付位置 | 历史日志或 archive |

同一项目只在 projects.md 维护执行事实；life-map 只保存方向与阶段里程碑，不保存逐项任务、剩余工作、情绪、故障或资料缺口；周、日安排引用 ID，不复制完整项目状态。某字段暂无依据就标未知，不为结构齐全猜测。

## 阶段与时间

项目状态使用候选、待安排、推进中、等待、暂停、完成或放弃即可；不强制每件事走完所有阶段。等待项注明阻塞条件及下次检查；完成项从活跃视图出列。

区分外部硬期限、自定目标日、执行时间块和复核日。自定目标可以协商，不能伪装成外部截止。

项目里程碑应描述可交付结果；台账只记录其计划结果与进度，不维护操作步骤、业务内容或任务教程。语言学习等持续投入不必为三天连续执行创建一个伪项目。

阶段规划保留里程碑与预计窗口；周安排明确每日结果；今日安排细化时间块。三者随现实双向更新，不逐日从零猜测。

## 模式与状态

当前状态来自近期明确表达或实际条件，注明时点。过去的情绪不能默认永久有效。
模式只保留能影响实际安排的候选解释，注明适用条件、依据、反例和复核点；不以观察次数机械生成置信度，不自动把诊断写成用户特征。
